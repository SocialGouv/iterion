## Context

PR #1670 (squash `6898e6c78`) landed the enforcement half of the fork review lane. `store.RunTrust` rides the run document (filesystem and Mongo), the queue message, resume, retry and fork; an untrusted run gets no publish grant (`injectForgePublishVars`, `runOwnsGrant`), no `forge_token` by either carrier, no commit status; the runner refuses a fetch that misses `RepoSHAExpected`; `launchWebhookTarget` keeps lane kinds disjoint and refuses an untrusted target without a pin; a board-mode route refuses provenance. `webhooks.Config.ForkLane` exists and nothing can set it; `orgusage.ForkAuthorSubject` has no caller. Nothing sets `RunTrustFork`.

**Main has grown trust readers since.** `admitRun` refuses an untrusted run without a per-run sandbox (#1773); `admitSandboxCredentials` refuses one no credential reaches (#1768, moving into ADR-161's resolver); the skill channel serves only owned skills — claw through `ExecuteSkillPinned`, claude_code through `--add-dir` (#1719); the connector resolution answers reads only and skips the workspace catalog tier for a run the tenant does not control (`pkg/connection/trust.go`, #1802). Forge clients stay in `pkg/forge`: a PR's client resolves through the team forge connection (`forgeConnectionForPR`) before the `forge_token` binding. The untrusted-input class freezes 155 acting prompts (196 reasons), `review-pr` among them (#1639's posture). Main does not keep the credential out of the agent's reach: a sandboxed agent holds its LLM credential as container env (`sandbox_credential.go`), Layer 2 substitutes only declared workflow secrets and cannot hold a forfait (docs/secrets.md), and the ambient stamp (`AmbientLLMRefused`), which refuses the launcher's own env, has no producer. And today no deployment can run a fork run: `runview.Launch` refuses an untrusted launch on the in-process path (no publisher persists the marker); the chart ships `ITERION_SANDBOX_OVERRIDE=none` to every runner unless `runner.sandbox.enabled` (off by default), which #1773 refuses; and under `networkPolicy.enabled` (on in `values-prod.yaml`) the release-wide policy closes the runner's proxy port to a sandbox pod, so a proxied run dies at its first egress.

**The branch is the floors, not the gesture.** It holds 25 untrusted-workspace floors behind a bench (`e2e/untrusted_*_test.go`: one hostile checkout through a real `Engine.Run` and real `claude`/`pi`/`opencode` spawns) and #1730's lesson: a guarantee established once and re-derived downstream from a mutable location fails, so it becomes a handle (`os.Root`) and an in-memory value whose zero value refuses. The gesture itself was never written. Every file the branch modifies still exists on main, but main rewrote them (`claw_backend.go` +2104 lines, `runtime/sandbox.go` +1402, `claude_code.go` +1085, `runner/loop.go` +973): 124 of 245 files conflict, so its diffs are a spec, not patches. One record is wrong: #1639 was closed on 28/10 as fixed by #1670, but the trust refusal in `stampHandoffs` exists only on the branch.

## Decision

1. **The opt-in is a gesture on a fork-lane config, never a record.** `ForkLane` is settable at creation (`POST /api/teams/{id}/webhooks`) and immutable: PATCH refuses a change, which would re-read parked debounce targets as the other kind. The gesture is a `/command` on a fork pull request, delivered to that config and routed by its own table (default `/revi` → `review-pr`). Only `github` may carry a fork lane: an allowlist, checked at creation and typed. GitLab names `refs/merge-requests/<iid>/head` as the unwired seam. Forgejo shares the `/command` path and the `refs/pull/<n>/head` pair, but its head-repository proof, numeric author id and ref have no witness. Generic has no pull request. The ordinary GitLab MR lane stops stamping "trusted" on a head neither project names: it fails closed like `forkGuardRefusal`.
2. **Who opts in.** A commenter whose live forge permission on the base repository reaches the route's `min_replier_role`, never below `developer` (write). The self-comment loop guard stays; the `AuthorizedRepliers` login short-circuit is not consulted on this lane, because a login is renameable.
3. **How the commit is pinned.** The handler resolves the pull request through the forge API and admits only a PROVEN fork of a PUBLIC base: open, head repository named and not the base, base visibility public (`forge.PullRef` gains it). A private base is refused, typed, before the bound is metered: #1670 resolves no `forge_token` for an untrusted run, so its clone cannot authenticate, and a token handed to that clone would persist in the fork's workspace (`.git/config`, the credential store). The handler launches on the base's `CloneURL` and `refs/pull/<n>/head` with `launchProvenance{Trust: RunTrustFork, ExpectedSHA: HeadSHA}`. An optional SHA argument narrows the gesture to that commit, or the launch is refused. A push between the gesture and the fetch is refused by the runner, naming both commits; a new head needs a new gesture.
4. **The base repository's configuration may stop a fork run, never steer or grant it.** `applyWebhookVarLayers` applies neither `LaunchVars` nor `OperatorLaunchVars` to an untrusted target; `trustedVarNames` stays empty; the hold label applies per Q2. Model routing resolves from the database cascade, because it spends the tenant's money, not the repository's. Gate relaunch and auto-fix stay refused on a fork-lane config.
5. **The bound.** `gateMonthlyCaps` meters a fork target twice: on the org's budget, fail-open as ADR-033 decides, and on `ForkAuthorSubject(org, provider, the PR author's numeric forge id)`, fail-CLOSED. This is the amendment: ADR-033 fails open because a quota is operator policy, not the security perimeter, and this subject is the perimeter against an outside party. `forge.PullRef` gains that numeric id; today it carries only the login. Its values follow Q4. The org purge matches the escaped key spelling.
6. **What the run may read and write.** It reads the base clone at the pinned commit (the base is its only remote, fetched before the sandbox starts), connector read operations and the bot's own skills through the pinned channel. It writes its sandboxed workspace and its own events and artifacts. Nothing reaches the forge, the board, the host capabilities, the tenant's memory (either way) or a hand-off seed (either way). Nothing the checkout declares is executed or loaded: its hooks, `.mcp.json`, `devbox.json`, `devcontainer.json`, `.env`, slash commands, context files and bot bundles. Plugin MCP servers are not booted either, because they would start inside the checkout.
7. **The container holds no credential, and its only egress is the credential's host.** `review-pr`'s reviewers hold `bash`, and a fork's diff can steer them. The run therefore spends a sealed API key or gateway credential that crosses as a Layer 2 placeholder; the sandbox proxy substitutes it in headers toward that credential's host. That host is the run's whole egress: `allowlist` with no preset, because `iterion-default` admits the code hosts, the registries and `**.googleapis.com`. A request to that host that authenticates with anything but the placeholder is refused, so a key of the attacker's own cannot carry what the run read out through the provider. Every channel the proxy cannot hold is refused, typed: a forfait (Layer 2 cannot substitute an OAuth credential), a file login, the launcher's ambient env, and the `ITERION_SANDBOX_TLS_INSPECT=off` hatch. Every untrusted run carries the ambient stamp, which `ambientStampRefusal` honours today and under which #1768's channel 2 stops counting. The rule is one input of ADR-161's resolver, the same on every admitted backend.
8. **Where the guarantee is enforced.** It is enforced in four layers, and every predicate is `Trusted()`, so an unknown trust loses. The server enforces disjointness, the pin and the bound at `launchWebhookTarget`, plus #1670's grant and secret refusals. Runtime admission enforces the sandbox and decision 7's credential at `admitRun`. The sandbox proxy enforces decision 7's egress. The floors read one value resolved per run from `runtime.WithTrust` and handed down: `delegate.Task`/`IOTask` carry it across the sandbox wire, and a child run (store stamp and wire) and a node's processes (`ITERION_RUN_TRUST`, cooperative) inherit it. It is never re-derived from the workspace. Every host-side read or write derived from the workspace goes through the workspace handle, `<workDir>/.claude`'s family and the catalog under `<workDir>/bots` alike. An untrusted run regenerates no catalog at all, because even through the handle the fork would author the orchestrator's routing table.
9. **Backend parity: every floor on both, or a typed refusal.**
   - Project settings: claude_code drops `project` and `local` from `--setting-sources` at the one builder every spawn takes. claw registers only iterion's own hook groups, from memory, and claude_code gets the same groups through `--settings`.
   - Skills: #1719, on both.
   - Slash commands: claw stops resolving the checkout's. claude_code gets them only through the floored project source.
   - MCP: neither backend autoloads `.mcp.json` or boots a plugin server. The bot's own stdio servers start from `/`, and strict mode is forced.
   - Memory: claw's `memory:` block and auto-memory are both withdrawn.
   - Host capabilities: one resolver, checked when the tool is called.
   - Credential: decision 7 on claw, claude_code and pi alike.
   - Other backends: pi gets its three floors. codex, opencode, grok and kimi refuse with `ErrUntrustedWorkspaceRefused`, and the protocol's zero value refuses.
10. **Where it runs.** Only where the run's sandbox resolves active, so #1773 stays the refusal. The in-process launch persists `Trust` and `RepoSHAExpected` instead of refusing (one code path, single-process and multi-replica). In the cloud, Q3 decides. The output follows Q1.

## Migration

Each unit lands alone and ports its rows of the branch's bench, each row seen red on main with the floor removed and green with it. U1–U5 cannot change a live run's behaviour, because nothing sets `RunTrustFork` until U6. Order: U1, then U2–U5 in any order, then U6, then U7 once Q3's chart prerequisite has landed.

- **U1, the carrier.** Covers the trust on `Task`/`IOTask` and every task assembler, the compile seam, the child stamp in both stores (conformance row), the process environment with `ITERION_DOTENV_FORCE` losing, the handoffs, and the in-process launch persisting the marker. Witnesses: the carrier, child-run and dotenv benches, `handoff_untrusted`.
- **U2, the handle (#1730).** Every host-side reader and writer derived from the workspace holds it: the mirror family, plugin hooks, owned skills, the skill channel. An untrusted run regenerates no catalog. `CopyFrom` is atomic and keeps the source mode. Witnesses: the `.iterion-managed` escape row, `CopyFrom` hardlink and concurrency, the pruner sidecar, and a checkout bundle whose `skills` links out of the workspace writing nothing (a trusted run regenerates as before); the raw-writer text guard as a comfort.
- **U3, agent configuration.** Covers the claude_code and claw settings and hooks, slash commands, pi, and the typed refusals. Witnesses: the real-CLI setting-source probe, every spawn path, and a hook veto through a dangling link.
- **U4, MCP, sources, memory, host capabilities.** Witnesses: the MCP-channel bench, memory in both directions, and a host tool named in `command:` refused.
- **U5, the sandbox and the credential.** The host-state floor resolves before the credential admission, which then judges the floored mount (ADR-161's `SandboxHomeState`). Otherwise #1768 would admit a run whose only credential is a login that is no longer mounted. Then decision 7: the publisher and the in-process launch stamp `AmbientLLMRefused` on every `!Trusted()` run, the crossing hands placeholders, and the network floor is the credential's host. Before ADR-161's U2 it lands at today's arms (`selectedAnthropicCredEnvForCLI`, `ClawSandboxCredential`, pi's), which become parity rows of ADR-161's bench. Witnesses: a devcontainer `postCreateCommand` canary, the host-state mounts, devbox; the container env holding the placeholder and no key value, with real `claude` and claw spawns authenticating through it; `api.github.com`, a registry and `storage.googleapis.com` refused, and a foreign key toward the provider host refused; forfait-only, file-login-only and ambient-only runs refused at admission.
- **U6, admission.** Covers decisions 1–5 and Q1/Q2/Q4: create-time `ForkLane` with the PATCH refusal and the provider allowlist, the GitLab MR fail-closed, the gesture, the private-base refusal, the var layers, the bound in both counter twins, and the delivery-row reasons. Witnesses: a real GitHub delivery replayed through the handler on a fake forge (fork admitted; same-repo, withheld head, private base, login-allowlisted non-writer and stale SHA refused, the private base before the bound is metered), a PATCH flip and a Forgejo config refused, the bound denying the N+1th run, and the metering error refusing.
- **U7, deployment and proof.** Covers Q3 in the chart and the publisher, plus `docs/webhooks.md`'s table rewritten to what ships. Proof: one live `review-pr` run on a lab repository's fork PR, through a real delivery, sandboxed under the prod values (`networkPolicy.enabled: true`). It is also the first cluster validation of the kubernetes driver's Layer 2. Its cost goes in the commit.

## Open operator decisions

- **Q1 — what the maintainer sees.** (A, recommended) A server-written note on the PR naming the run link and the pinned commit, and nothing the run wrote. (B) Only the console and the delivery row. (C) The review posted by a separate comment-only credential, which puts prose an attacker can steer under iterion's identity and needs its own security review.
- **Q2 — the hold label.** (A, recommended) It vetoes the gesture, because it stops a run and never steers one. (B) It is ignored, following #874's letter and the `/command` rule that labels pause only automation.
- **Q3 — where fork runs execute in the cloud.** (A, recommended) A dedicated runner pool that resolves a kubernetes sandbox for every run, named by the fork-lane config and stamped as `RunnerPool` by the publisher, behind ADR-154's pool boundary (#2965). Its standing policy admits the siblings to the pool's runner pods, so the per-run proxy composes with `networkPolicy.enabled`; the release-wide policy does not (cloud-deployment.md § NetworkPolicy egress). Chart work: #2965 and a per-pool `runner.sandbox.enabled`. (B) `runner.sandbox.enabled` for the whole deployment. Every trusted run whose bot declares a `sandbox:` moves into a sibling pod, and the release-wide policy must be off or open to the proxy port, which no value does today. (C) Self-hosted only, with the cloud refusing as it does today.
- **Q4 — the per-contributor bound.** (A, recommended) Runs and dollars per month, held on the org beside its quota, with a platform default in the settings ladder (proposed: 20 runs, $20) and an explicit unbounded value as the escape hatch. (B) On the fork-lane config; the key has no config segment, so two configs of one org would share one counter under two caps. (C) No bound, with the gesture as the only one.

## Consequences

- A fork contributor can get a review, and only after a write-level maintainer says so, for one commit of a public repository, inside a sandbox that holds no credential value, with nothing published by the run.
- The lane spends an API key or a gateway credential: a team funded only by a forfait is refused, typed. The residual is spend: a steered agent can use the placeholder through the proxy for the run's lifetime, outside iterion's meter.
- The floors protect any future untrusted class (a mirror, an imported tree), because they read `Trusted()` and not `IsFork()`.
- Behaviour changes for trusted runs at two points: an ordinary GitLab MR whose payload names neither project is refused, and the in-process launch carries the marker.
- Each unit reviews against the branch's rows rather than re-deriving the threat model, which already cost six rounds.
- The per-author row stores an outside contributor's numeric forge id under the 400-day TTL, purged with the org.
- Out of scope: the GitLab and Forgejo fork lanes; a private base, whose fetch needs a token kept out of the workspace (a runner-owned clone, then a credential-free local clone into the sandbox); ADR-161's resolver itself, to which U5 adds one input and the placeholder crossing; and the forge-integration toggle that would provision a fork-lane hook.
