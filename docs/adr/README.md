# Architecture decision records

- [154 — The sovereign pool boundary](154-the-sovereign-pool-boundary-is-a-namespace-and-an-enforced-proxy.md): in the release's shared namespace, the pool's own ServiceAccount and Role without the policy-authoring verbs, a standing default-deny policy over the pool's pods, and an enforced egress proxy out of the pod.
- [138 — Forge provisioning identities](138-forge-provisioning-immutable-identities.md): immutable webhook epochs, optimistic activation, write redirects and the hybrid reconciler boundary.
- [156 — Bearer token hashing doctrine](156-bearer-token-hashing-doctrine.md): a stored bearer token is its unsalted SHA-256 digest (CSPRNG ≥ 128 bits); HMAC under a derived key is for derivations, never for a human-chosen input.
- [155 — Reserved capacity is a durable allocation](155-reserved-capacity-is-a-durable-allocation.md): one ledger behind the window, dollar, slot and pool axes, an acquire that is a single compensated write, a settle, a sweep that carries correctness — and reservable execution capacity.
- [160 — Legal content is deployment configuration](160-legal-content-is-deployment-configuration.md): the legal notice, privacy policy, terms and accessibility statement ride the chart's `config.legal.*`, never the bundle nor the database.
- [151 — board.* behind the action seam](151-board-actions-behind-the-action-seam.md): a registered native transport serves `board.*` in process with no credential, and a tool node declares `capabilities:` exactly like an agent or judge — one grant surface for every node kind, check-only unless the node opts in.
- [161 — One resolver decides the credential a call spends](161-one-resolver-decides-the-credential-a-call-spends.md): per-backend arms behind one `Resolve` over the run's credentials and the attempt's carried environment; dispatch builds from its `Spend`, admission, meter and the pool's fine table read it verbatim, a refusal is one type, the stamp binds every backend.
- [163 — The gateway price feed syncs into the database and rides the IPC](163-the-gateway-price-feed-syncs-into-the-database-and-rides-the-ipc.md): operator pricing auto-syncs into org/team feed documents on a configurable period, one elected replica reconciling; the server folds the effective table at every launch (fresh feed entries over the operator table for the ids they carry, team over org) and seals it in the run bundle; the runner plants it on the run's environment where the catalog reads it between the host IPC record and the operator table; staleness is first-class and steps down, never refuses; sources are adapters (`modelsdev`, `scaleway`, `litellm`, `exec`); manual sync through the API and `iterion remote price-feeds`; the `_gateway_spec` record carries `feed:<name>` with its age.
- [165 — Codemode runs the model's code in a credential-less child process](165-codemode-runs-the-models-code-in-a-child-process-behind-the-tool-door.md): one tool whose argument is code, executed harness-side, whose only capability is calling the node's own tools through `toolDispatcher.dispatch` — the same function the model's loop uses, so the gate cannot drift; confinement is kernel primitives applied before the interpreter (goja bounds no heap, ADR-098 F19), the host holds no credential, every bound carries an override and a platform ceiling, and "usable in cloud" is declared by an **in-pod** bench because production ships `ITERION_SANDBOX_OVERRIDE: none`.
- [166 — Model capabilities ride the price feed](166-model-capabilities-ride-the-price-feed.md): a gateway model's accepted reasoning efforts join its prices and window in ADR-163's feed, their database seat. A `declared` source answers from its own config and never ages. A `platform` scope folds below every org and team. Efforts fold field by field, beside the price entries, team over org over platform. The runner reads the run table first and `OPENAI_COMPATIBLE_REASONING_EFFORTS` only as a fallback, and the sandbox crossing carries the host's merged answer. A platform `scaleway` preset feed replaces `OPENAI_COMPATIBLE_CATALOG_PROVIDER`. There is no per-integration capability seat; a team-level declaration is the escape hatch.
- [167 — A shared gateway bounds its alive runs](167-a-shared-gateway-bounds-its-alive-runs-through-the-run-admission-ledger.md): a gateway's host is a capacity subject, `gw:<host>`, of the per-key cap's ledger — stamped on every run that seals a key dialling it, reserved by the publisher after the keys and before the run is written, a refused launch parked before start with its retry armed in the same write. The runner keeps the place through a redelivery and re-asserts it before any direct resume, and a launch re-checks it after its write. A subbot tree is one place, a parked launch that never started runs the current bot, the bound is observed first then enforced behind a guard on alive runs whose subjects do not name their host, `max_wait` bounds the whole wait, and the subject is the host alone in v1.
- [168 — An event source is a connector package](168-an-event-source-is-a-connector-package.md): the inbound half ADR-098 deferred. `triggers.yaml` declares a verification contract (credential, timestamp, body encoding), which the ingress pins at bind time, and per trigger its outputs, filters, loop guard, sample, hook provisioning and polling. Expressions see a sanitized event and never the request. A durable intake row is acknowledged before any matching; effects run as (intake, subscription) pairs with a recoverable launch identity. A `trigger.Subscription` binds a connection's trigger to a bot with a var map, and `Mode` gains `deliver`, refused until #3136. Pollers are elected, not exclusive: intake comes before a fenced, monotonic checkpoint. Every webhook lane charges quota only after authentication. Forgejo migrates under one authority at a time. After it, a new source is files under `connectors/<id>/`.
- [162 — The fork review lane is a gesture on floors that land first](162-the-fork-review-lane-is-a-gesture-on-floors-that-land-first.md): a write-level maintainer's `/command` on a fork-lane config admits one pinned commit of a public base, on a dedicated sandboxed pool, bounded per author (20 runs / $20 a month by default) and noted on the PR by the server; the untrusted-workspace floors (carrier, workspace handle, both backends, MCP, a sandbox that holds no credential, on a network proven to admit only its provider and its proxy) land before it, re-implemented from main with `fleet/c3-fork-lane-2` as the spec.

- [163 — The gateway price feed](163-the-gateway-price-feed-syncs-into-the-database-and-rides-the-ipc.md): operator pricing syncs into the database on a configurable period and reaches runners through the IPC record; the operator table stays the floor, a stale feed steps down with a warning never a refusal, sources are pluggable adapters and a manual sync names every change.
- [169 — A run's settings come from the database, and the catalogue names roles, not vendors](169-a-run-reads-no-environment-and-the-catalogue-names-roles-not-vendors.md): the catalogue authors literal routing fields and behaviour knobs, and every re-target is an `llmroute` override cell at a database level — `ITERION_VIBE_*` and `ITERION_MODERNIZE_EFFORT` retire from the bots, the pod env and `ITERION_BOT_VARS_ENV_PINS`, with a guard against the class coming back; the review topology names roles (`auto | single | paired`, `reviewer` / `reviewer_alternate` / `converge`) and `mono_family` is deleted, the alternate being a routing decision like any other.
- [170 — An issue trigger is a re-armable lane](170-an-issue-trigger-is-a-re-armable-lane.md): a label applied to an issue is a request a person can make again, not an event that happens once. Its claims form a sequence per (repository, issue, trigger) — generation-keyed delivery rows on the direct lane, deterministic card ids on the board lane — decided before anything is metered. An event is known by the forge's delivery id, or its body hash when none, and every event not launched for leaves a record under that identity, so a redelivery stays a no-op after the claim ends. An unreadable lane answers 503. Comment commands are unchanged.
- [171 — A tool node's declared output is a contract](171-a-tool-nodes-declared-output-is-a-contract.md): a `command:` / `script:` that declares `output:` and prints non-empty stdout that is not a JSON object fails at that node, and a tool body that reads a declared field its tool producer did not print is refused before it runs — both `TOOL_FAILED_PERMANENT`, not retried, not redelivered, in place of the `{"result": …}` wrapper and the literal placeholder `bash -c` used to run. Each refusal has an operator dial (`ITERION_STRICT_OUTPUT_VALIDATION=0`, `ITERION_STRICT_OUTPUT_REFS=0`), a setting of the engine's process and never a bot's. A node without `output:`, empty stdout, an object missing fields, postcondition nodes, registry tools, actions, and human, compute and subbot producers keep the lenient reading; the engine's directive lines are not part of an answer, and a join merges colliding outputs in branch-id order.
- [172 — A forge delivery is routed by the subscriptions its integration projects](172-a-forge-delivery-is-routed-by-the-subscriptions-its-integration-projects.md): the forge cutover ADR-046 staged — the spine becomes the forge router, the webhook tail stays the forge effect. An integration projects one subscription per (bot, issue route), bound to it and selected by that binding, from its bots' manifests (`forge.labels`) and its per-bot `bot_triggers`; a label starts every bot whose row claims it, each in its own mode and with its own `context_vars`, through the tail's Delivery claims. A lane is per bot and is read across both claim stores, so a flip either way never launches twice; rows whose manifests moved answer `503 subscriptions_stale`; nothing claimed answers `200 filtered`, never a 4xx. The switch is per integration and per lane, `legacy` by default; P1a ships the issue-label lane.
- [173 — Experimental delivery mode](173-experimental-delivery-mode.md): while the project is experimental the merge queue gates on the light layer (`test` over unit, studio and native exec, `vendor-check`, `golangci`, `brand`, `revi/review`); `race-shard`, `test-e2e`, `mongo-conformance` and `cloud-e2e` run on a debounced push to `main` (the first push without a green heavy run in the last `CI_HEAVY_EVERY_HOURS`, #3737), nightly, on a dispatch and on a `ci:full` pull request; `race` and `mongo-conformance` are held out of the ruleset; a red `main` is rerun once, then quarantined as a flake or reverted as a regression; exit criteria bound the regression rate, the flake count and untriaged reds.
- [174 — A personal access token invites by email only](174-a-personal-access-token-invites-by-email-only.md): a PAT mints one team-scoped thing, an invitation whose token only the invited address's mailbox receives (`auth.MintEmailedInvitation`): the token stays sealed in `pkg/auth`, leaves by a synchronous email after the cap confirmations, the invitation expires no later than the PAT, the rank caps are unchanged, and an instance with no mailer refuses it; a studio session keeps the link.
- [175 — The org is the envelope of budget and capacity](175-the-org-is-the-envelope-of-budget-and-capacity.md): amends ADR-048. Limits share one value convention (0 inherits, −1 unbounded) and one resolver: team, org, plan (database, then a Helm file), env. The org bounds capacity as well as the monthly budget (`MaxConcurrentRuns`, `LaunchRatePerMin`, `MaxTeams`, org-keyed webhook and memory counters). A team carries an optional ceiling, charged by the gate and by the runner. Ceilings may oversubscribe the org, and guarantees are floors. On concurrency the gate chooses and the publisher enforces through `CredSlotStore`, after ADR-167's stamping, which the operator brought forward. Every fail-open is counted. Authenticated requests are rate-limited per principal, then per team. Each piece is built on a named trigger.
- [176 — A launch past capacity waits as a run](176-a-launch-past-capacity-waits-as-a-run.md): amends ADR-175 D4 for every concurrency axis. Every launch surface creates the run at once; past capacity it waits in a new status, `waiting_capacity`, naming its axis, never refused, lost or replayed. A leased scheduler admits it through `CredSlotStore`, whose rows gain typed subjects (`bot:`, `team:`, `org:`, `rate:`, beside keys and `gw:`), FIFO per subject and round-robin across teams, and only then publishes it. Non-time-resolvable refusals (monthly budget, policy, fork bounds, all slots reserved, maintenance) stay refusals. The per-bot ceiling of #3845 is the first subject. Proposed.
- [177 — Security posture is a dedicated bot that consumes the forge's alerts](177-security-posture-is-a-dedicated-bot-that-consumes-the-forges-alerts.md) (Proposed): Vetty keeps the per-PR lane; a new scheduled bot reads the forge's alerts (code scanning, Dependabot) instead of re-scanning, triages only the delta with one LLM pass, proposes dismissals with their reason (`dry_run` before `enforce`), files remediation lots whose PRs Vetty judges, and reports posture metrics, a dead scan channel and a blocked Renovate group included.

One decision per file, named `NNN-kebab-title.md`, where `NNN` is the next
free number. The number is the record's **identifier**: it is cited from code
comments, commit messages, pull requests and other ADRs, and from places this
repository cannot reach — a chat thread, a ticket on another forge, someone's
notes. That is why a number, once published, is never reassigned and never
renumbered: doing so repairs the links inside this tree by silently breaking
every citation outside it.
