# ADR-102: The YAML author twin — a draft, never a truth

**Status:** Accepted (2026-09-23, lot 5 of #1010: PRs #1631, #1664, #1720 and the PR that closes #1584)
**Relates to:** [098-dsl-versioning-and-authoring-surface.md](098-dsl-versioning-and-authoring-surface.md) § 4 (the authoring surfaces: a YAML form, "if lot 5 justifies it, is a conversion surface only"), [100-dry-run-at-the-executor-seam.md](100-dry-run-at-the-executor-seam.md) (the dry run a document is validated under), the operator's arbitrations of lot 5 recorded on #1010 and #1584 (a conversion surface only; the surfaces that read a document)

## Context

[098-dsl-versioning-and-authoring-surface.md](098-dsl-versioning-and-authoring-surface.md) allowed a YAML form of the `.bot` if lot 5 justified it, as a conversion surface only. The authoring probe measured it on 2026-09-22 ([dsl-authoring-probe.md](../references/dsl-authoring-probe.md)): a mid-size model writing the YAML twin did no worse than with the `.bot` — 4.0 errors at the first draft against 5.3, 2.7 rounds to green against 3.3, 821 lines read against 912, 30 requirements of 30 on both sides. The same measure showed what the twin does not do: it does not remove the lexical class of mistakes, it moves it — a plain YAML value holding `: ` is a mapping, and an edge string's inner quotes nest badly.

What the lot then had to settle is what a `.bot.yaml` IS to every surface that can meet one: a launcher, a packer, a content hash, the cloud store, `validate`, `fmt`, `diagram`, the catalogue.

## Decision

1. **A draft, never a truth.** `x.bot.yaml` is a way of writing `x.bot`; only the `.bot` is a program. A document is refused by name, before any effect, at every door that would launch or store it: `bundle.Detect` (by the name, before the disk), `runview.Service.Launch` (before the queue persists a run), the compile floor `runview.compileUnit`, a subbot's `source:` (C305), the HTTP source resolver and the launch handler (`error_code: author_document`), the bot-source store's `Validate`, MCP `local_run` and `local_resume`, the remote upload, the schedule. One typed sentinel, `bundle.ErrAuthorDocument`, names the command that writes the `.bot`.
2. **Never transported.** One file-only predicate, `bundle.IsDraftEntry`, keeps a document out of a `.botz`, of both content-hash walkers, of an extraction, of a snapshot, of the store's walkers and materialiser and of a bot install. An extraction creates no directory from a directory entry: the tree it writes is the archive's files, what the hash sees, so two archives that hash alike land the same tree in the shared cache slot. A bundle without a twin keeps its exact hash; an older archive carrying one is admitted, the twin left inside.
3. **Read, as the `.bot` it stands for, by the surfaces that write or inspect a `.bot`.** `validate` reads it in the unit and the bundle of that `.bot`, at the document's own positions, `--exec` included; `fmt` gives it its canonical YAML form and converts both ways (`--to bot|yaml`), each conversion proven the same program; `diagram` draws that `.bot`; the MCP `local_validate` reads it. `validate` and `diagram` share one construction of a document's unit and one E054, and `diagram` runs, once the unit is loaded, the very stages the `.bot`'s own diagram runs (`runview.CompileLoadedUnit`): what refuses the `.bot` refuses the document. A manifest export naming the `.bot` a document stands for is that `.bot`, written or not.
4. **Spelled into `.bot` text, read by the one parser.** `author.Parse` spells the YAML into `.bot` text form by form from the property registry, the parser reads that text, and every position is mapped back onto the document: one grammar, one reading. An edge keeps the `.bot`'s edge line, as a string. `author.Write` renders an AST as YAML in the registry's order. What YAML reads otherwise than it is written is refused where the converter can see it, never re-spelled: a number YAML reads in another base or with a `+` sign, a leading 0, an underscore or an exponent (`010` — the octal 8, where the `.bot` reads 10 — `0x10`, `+3`, `01.5`, `1e2`), a bool spelled otherwise where text is taken (`True`), a `!` YAML drops as a tag before a value of any style. A `-` is kept where the value is text. The writer spells what the reader takes, and `fmt` proves it: a document is written only once it reads back as the program.
5. **A rewrite never loses what the author wrote in silence.** `fmt` refuses to rewrite in place a document that carries YAML comments (the writer keeps none) or a text the `.bot` reads otherwise than it was written (E053), and keeps a document's BOM and line endings. It sees the comments yaml.v3 attaches to a value, and reads off the source those yaml.v3 drops: a flow collection's, as yaml.v3's scanner reads them (the one after an opening bracket, the one between a tag and its bracket), and a directive line's (`%YAML 1.1 # …`) — see below for the one place it does not. A conversion under `--force` replaces its target whole: it names what the target carried that the new text does not — the comment lines, counted with the first named (a `.bot`'s frontmatter comments included), and a `.bot`'s frontmatter keys, compared by key since the writer spells the frontmatter its own way — or, for a target that is not one YAML document it can read (not YAML, comments alone, several documents), that it could not count them.
6. **One reading of a catalog identity.** A frontmatter block is taken off the head of a file as the parser files it (`parser.Frontmatter`) and decoded once (`workflowfile.DecodeFrontmatter`) — for the catalogue, the author writer and `fmt`'s notices alike — so a document's `catalog:` is what the catalogue reads off its `.bot`.
7. **`dsl:` is required** (E052): a new surface has no profile to guess.

## What is not promised

- **The lexical class is moved, not removed.** YAML has its own traps. The syntax errors an author meets first name the spelling that avoids them — every cause, when the scanner's one message has several — and the documentation states the three rules a YAML author needs that a `.bot` author does not; other scanner messages still come bare (#1783). One trap is no error at all: a space and `#` end a plain value and start a comment. `fmt --to bot` counts the comments it leaves out of the `.bot` and names the first; `validate` reads the value that is left (#1780). A block scalar under a property whose value is one word keeps its final line break until the run refuses it (#1781).
- **Comments.** They are not carried either way: each conversion counts the ones it leaves behind, and a `--force` the ones it replaces (#1760 would keep a document's through `fmt`). A comment after a `...` end marker, which yaml.v3 does not read, is not seen by `fmt`, which rewrites it away (#1784).
- **The spelling of a round trip.** `--to bot` writes the frontmatter as the writer spells a `catalog:` (a list as `[a, b]`), whatever the original `.bot` wrote.
- **Case.** `IsAuthorDocument` folds the suffix's case, `IsWorkflowFile` does not (#1762); neither `fmt --to bot` nor `diagram` takes a document whose `.bot` name they would not read back.

## Alternatives rejected

- **A document discovered or launched.** Two truths that can diverge, and a matrix of consumers nobody maintains ([098-dsl-versioning-and-authoring-surface.md](098-dsl-versioning-and-authoring-surface.md) § 4).
- **Reading the YAML straight into the AST.** A second interpretation of every property, beside the parser's; spelling the text keeps one.
- **Edges as YAML mappings.** A second grammar of edges; the `.bot`'s edge line is the one a reviewer reads.
- **A document travelling inert in a bundle.** It would move the bundle's hash, and break `botlock` for every dependant, for a file no runner reads.
- **Recreating an empty directory at extraction.** Two archives that hash alike would land different trees in one cache slot, whichever was opened first.

## Consequences

- The author JSON Schemas (one per profile, and a combined one) and [author-schema.md](../references/author-schema.md) are rendered from the property registry, and `task dsl:check` holds them fresh; the page's top-level keys are held to the schema's root, its value forms to the forms the registry uses.
- Every ` ```yaml author ` fence of the documentation is read by the converter and compiled in CI, a valid one in its canonical form; every standalone or `fragment` ` ```iter ` fence round-trips through the author document as the corpus does.
- Follow-ups opened at #1720's merge: #1760 (comments through `fmt`), #1761 (the latency of the E054 proof), #1762 (the case of the suffix), #1763 (`validate`'s reading of a stale `.bot` beside a document, and the form of `bot_path`), #1764 (one parse per bot at discovery). And with this ADR: #1780, #1781, #1783, #1784 above, and #1782 (the engine's wip-bank must prove it is in its own worktree before committing — found while this lot was reviewed).
